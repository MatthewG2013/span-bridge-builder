# Span · 造桥模拟器（初版）设计

日期：2026-11-22

## 目标

做一个打开即玩的网页版造桥模拟器：在预算内连接两岸、铺设路面，让卡车安全通过。初版强调「搭桥 → 试桥 → 看应力 → 改进 → 上传成绩」的完整闭环，而不是单纯画线。

## 范围

- 3 个关卡：溪谷、中央石柱峡谷、大峡谷。
- 2 种结构材料（木材、钢材）+ 1 种路面材料。
- 建造、撤销/重做、删除、预算校验、路面连通性校验。
- 基于位置约束（PBD）的实时结构受力、梁件过载断裂、变形与坍塌。
- 卡车沿路面行驶、对桥面施加动态载荷；通过则胜利，桥断/落水/超时则失败。
- 昵称存档：每个昵称每个关卡一份设计，保存在服务端 JSON 数据库。
- 服务器排行榜：按建造成本升序、通过时间升序排名。
- 响应式 Canvas 画面，桌面优先，支持触摸指针。

非目标（后续版本）：账号密码体系、钢索、多种车辆、关卡编辑器、多人实时。

## 技术方案

纯 HTML + TypeScript，无前端框架、无运行时第三方库。

- 前端：原生 DOM + Canvas 2D。TypeScript 编译为原生 ES Module，由静态服务器直接分发。
- 物理：自研 Verlet / Position-Based Dynamics。节点是质点，梁是距离约束；迭代求解后计算应变，超过材料阈值持续数帧即断裂。卡车载荷施加在桥面最近的两个节点上。
- 后端：Node.js 原生 `http` 模块，零运行时依赖。提供静态文件与 JSON API。
- 存储：`data/db.json`，原子写入（临时文件 + rename），单进程写队列串行化，避免并发覆盖。
- 构建：`tsc` 双配置分别输出浏览器代码与 Node 代码。共享关卡与类型放在 `src/shared`。

## 架构

```
src/shared/types.ts       共享类型
src/shared/levels.ts      关卡几何、预算、锚点（前后端共用）
src/client/physics.ts     PBD 物理、材料参数、路面寻路（纯逻辑，可测试）
src/client/renderer.ts    Canvas 场景与游戏对象绘制
src/client/game.ts        状态机、输入、卡车、胜负判定
src/client/api.ts         后端调用
src/client/ui.ts          HUD、弹窗、提示、排行榜 DOM
src/client/main.ts        启动与装配
src/server/server.ts      HTTP 服务器、路由、静态文件
src/server/store.ts       JSON 存储与查询
src/server/validation.ts  请求校验
public/index.html         页面骨架
public/styles.css         视觉样式
```

### 数据流

1. 页面启动拉取 `/api/health`，恢复本地昵称，载入关卡。
2. 建造只修改内存中的 `Build`（节点 + 梁），实时计算成本并绘制。
3. 点击测试：校验路面连通 → 创建模拟 → 每帧物理步进、卡车沿当前桥面推进、施加载荷 → 判定胜负。
4. 胜利后 `POST /api/results` 上传成绩，刷新排行榜；失败只展示原因。
5. 保存设计 `POST /api/designs`；切换关卡或输入昵称后可 `GET /api/designs` 恢复。

### 关键接口

- `GET /api/health`
- `GET /api/leaderboard?levelId=`
- `GET /api/designs?nickname=&levelId=`
- `POST /api/designs` — `{ nickname, levelId, name, build }`
- `POST /api/results` — `{ nickname, levelId, cost, time, beams }`

服务端校验昵称长度、关卡 ID、节点/梁数量、引用完整性、数值范围与请求体大小；保存每个昵称每关的最佳成绩。

## 玩法与数值

- 世界坐标 1280 × 720，建造网格 16 px，单梁长度 24–144 px。
- 材料：
  - 路面：便宜、中等强度、强制的通行面。
  - 木材：轻、便宜、强度低。
  - 钢材：重、贵、强度高。
- 成本按梁长比例计算，建造时实时扣预算；拆除返还。
- 路面必须从左侧锚点连通到右侧锚点（或经由中央锚点）才能测试。
- 卡车有 25 秒通过时限；桥面节点掉入河谷、路面断开或关键梁断裂即失败。
- 应力颜色：绿 → 黄 → 红；红色梁件即将断裂。
- 排名分数只取决于成本与时间，鼓励用更少的材料造出更巧的桥。

## 视觉

- 「黄昏工程蓝图」风格：深蓝夜空、暖橙地平线、青蓝峡谷、发光网格。
- 建造模式显示细网格与坐标提示；测试模式隐藏网格、显示应力光晕与粒子碎屑。
- HUD 位于左右两侧：左侧关卡/预算，右侧材料/操作/排行榜；小屏折叠为上下布局。
- 所有图标用内联 SVG 或 Canvas 绘制，不依赖外部字体与图片。

## 错误处理

- 网络/服务器异常：顶部状态点变红，保存/上传操作显示可读错误，不阻塞继续游玩。
- 存档数据损坏：服务端捕获解析错误并备份为 `.corrupt` 文件后重建空库。
- 非法请求：返回 400/413/404 JSON，不写入磁盘。
- 物理异常：位置/速度限幅；NaN 检测后终止测试并提示。
- 本地存档与服务器存档冲突：服务器为准，载入前提示会覆盖当前建造。

## 测试与验收

- `npm run build` 零 TypeScript 错误。
- `node --test` 覆盖：路面寻路、预算成本、物理断裂、存储校验。
- API 冒烟：健康检查、保存/读取设计、提交成绩、排行榜排序、非法请求拒绝。
- 浏览器验收：三关可建造；能完成至少一关；失败动画与提示正常；刷新后能载入服务器存档；排行榜显示。
- 手动确认无控制台报错，页面在 1440×900 和 1024×768 下布局不溢出。
